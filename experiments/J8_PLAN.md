# J8 — 给剪枝同一个编码器，再看动作族的不对称是否还在（预注册，2026-11-23 22:02，结果未出）

## 0 为什么这一轮会决定头条

Referee A 对 Fig. 2 / Table 5 的异议，我核对后**成立**：剪枝臂在 `m5_rd_v2.json` 里是 **205–207 B/primitive**
（fp32 属性 + zstd），量化臂是 **14.8–56 B/primitive**（容器）。所以剪枝族在图上那条线本质是 `1.14 / keep`
的双曲线——它的"压缩"几乎全部来自删除本身，**没有任何属性编码**。

于是"剪枝在任何资产上都没有可行配置"这句，可能是关于"我们没给剪枝编码器"的陈述，而不是关于动作的陈述。

## 1 三种臂（同一检查点、同一容器、同一 q、同一部署视图）

| 臂 | 构造 | 码率 | 覆盖损失 |
|---|---|---|---|
| `quant-only` | 全模型 + 8-bit 容器 | `bpp8 · n` | 已测（Table 12 的 d0 行：15.9× / 5.57 pp） |
| `prune-k only` | opacity top-k，**不编码** | `1.14 / k` | 已测（p90：1.15 pp …） |
| `prune-k + container` | top-k 后**用同一容器**编码 | `bpp8 · k · n`（k=0.9 → ≈17.7×） | **本轮测量** |

`bpp8 = 14.84`（实测的 quant8 规格 B/prim），fp32 记账 236 B/prim，两族用**同一个**每基元成本，避免"给谁便宜"。

## 3 已知的口径风险（先说，避免事后找理由）

1. `_quantize_splats(bits=8)` 只量化 SH 系数（颜色），不动几何。容器真实的 A6 是 gp8-6-6_c9_sh3（几何也量化）。
   因此本轮对剪枝臂**偏保守**（多背了一份颜色损伤），对结论方向有利，不会美化剪枝。
2. 本轮只测 8-bit 一个深度、两个资产、三个 keep 率；不测 finetune、不测 certified coreset。
3. 每个臂的 rate 用实测的 `bpp8` 记账，不是逐个打包测量的字节数——差在 zstd 对更少行的效率，量级 <10%。
4. 与 J7 一样，两轮的 q 可能不同（取决于归档切分），**只在轮内比较**。
