# M2 结果：属性精度地板（每类属性各花几位才不亏）

预注册规格：`experiments/METHOD_PLAN.md`「M2 规格」小节（2026-11-13，17:00 前写入）。
数据：节点 2139188，4 个场景 × 28 个变体（`AFQ_VARIANTS`），`--factor 4 --gt-convention archive --fidelity --lpips-net alex`，
dump 用时 17:14–17:31，npz 共 7.9 GB；分析 `m1_analyse.py --n-splits 400`（19:12–19:23）。
原始数字：`experiments/artifacts/a4/m2_rd.json`、`m2_rd_digest.json`。

## 1. 判定：`dead_write_N14` —— 但这个判定是**判据缺陷**，不是方法失败

分析器的输出（7 个码率点，55 秒前才跑完）：

| 判据 | verdict | 通过的码率点 |
|---|---|---|
| D1 覆盖支配 | **False** | 1/7（只有 5.0×） |
| D2 保真不劣 | **False** | 1/7（只有 5.0×） |
| D3 近无损档 | True | 2/7 |

为什么只有一个点有对照：M2 的变体集是**属性阶梯**，它的字节区间是 **5.62×–10.73×**，
而剪枝基线最狠只到 `p20 = 5.00×`。于是

- 2.0×、3.0×：QFP 曲线根本不在这个字节上（最便宜的成员 `m16_o8_sh8` 已是 3.69×，
  而 `m16_o8_sh8` 属于 M2 网格里的 SH 支线；主支线最便宜的是 `m20_o8_sh4 = 5.69×`）→ 无对照；
- 7.0×、9.0×、12.0×、16.0×：剪枝族不存在（`p20` 封顶 5.00×）→ 无对照；
- 只剩 5.0× 一个点：QFP 少损失 **+18.74 pp**，区间不含 0。

也就是说「D1 不成立」的真实含义是**这一轮的变体集和剪枝基线几乎不重叠**，判据在 6/7 个点上市无法测量。
这是我在写判据时的设计错误：判据必须与变体集的字节覆盖区间共同设计。已记入 N14，并在
M3 里修正（`METHOD_PLAN.md` 的 M3.4a 修订：E1 只在两条曲线共同覆盖的 `{3,5,7,9,12}×` 上评估，
且门槛从「6 点中 5 点」改成「5 点中 4 点」；修订写于 M3 任何数据落盘之前）。

**因此 M2 不作为方法成败的判定轮，它的价值是机制：11 个几何标量里到底哪个贵。**

## 2. 真正的结果：属性精度地板

覆盖损失 pp / ΔPSNR dB（负 pp = 变差；dB 正 = PSNR 掉了多少）。

### 2.1 位置（means）是唯一的贵项

| 变体 | 码率 | bicycle | flowers | stump | treehill |
|---|---|---|---|---|---|
| `m12_o8_sh4` | 6.13× | −19.01 / 4.61 | −16.12 / 2.66 | −32.97 / 6.26 | −7.88 / 0.17 |
| `m14_o8_sh4` | 6.01× | −4.69 / 1.25 | −5.20 / 0.74 | −10.62 / 2.19 | −1.52 / 0.03 |
| `m15_o8_sh4` | 5.96× | −1.60 / 0.40 | −1.94 / 0.26 | −4.04 / 0.83 | −0.45 / 0.01 |
| **`m16_o8_sh4`** | **5.90×** | **−0.45 / 0.13** | **−0.60 / 0.08** | **−1.23 / 0.25** | **−0.13 / 0.00** |
| `m17_o8_sh4` | 5.85× | −0.13 / 0.06 | −0.18 / 0.03 | −0.36 / 0.07 | −0.06 / 0.00 |
| `m20_o8_sh4` | 5.69× | −0.02 / 0.04 | −0.03 / 0.01 | −0.06 / 0.01 | −0.04 / 0.00 |

**16 bit 是硬地板，15 bit 就掉 1.6 pp（bicycle）/ 4.0 pp（stump）**。原因不是绝对精度不够，
而是**误差必须相对基元自身的尺度**：场景 10 m 用 16 bit = 0.15 mm，树叶的 σ 是 1–2 mm，
误差一旦超过 σ 的百分之几，投影到屏幕的覆盖就变形。这条与 M1 的 `iso_means12` 结果一致
（M1：`iso_means12` = −19.01/−16.12/−33.04/−14.20 pp，正是本表的 `m12` 行，两轮互证）。

### 2.2 视图相关项（SH）：3 bit 是近无损边界

| 变体 | 码率 | bicycle | flowers | stump | treehill |
|---|---|---|---|---|---|
| `m16_o8_sh8` | 3.69× | −0.43 / 0.10 | −0.58 / 0.06 | −1.18 / 0.23 | −0.10 / 0.00 |
| `m16_o8_sh6` | 4.54× | −0.43 / 0.10 | −0.58 / 0.06 | −1.18 / 0.23 | −0.10 / 0.00 |
| `m16_o8_sh4` | 5.90× | −0.45 / 0.13 | −0.60 / 0.08 | −1.23 / 0.25 | −0.13 / 0.00 |
| **`m16_o8_sh3`** | **6.94×** | **−0.67 / 0.34** | **−0.73 / 0.27** | **−1.61 / 0.44** | **−0.22 / 0.33** |
| `m16_o8_sh2` | 8.43× | −2.52 / 1.11 | −2.08 / 1.27 | −7.84 / 2.26 | −0.85 / 1.25 |

SH 从 8 bit 砍到 4 bit（3.69× → 5.90×，字节几乎减半）**只花 0.10–0.25 dB**；
3 bit 是还能保持 ≤1 pp 的最后一档；2 bit 立刻崩（stump −7.84 pp）。
**这正是 M1 之后近无损前沿从 4.92× 前移到 6.94× 的来源**：不是换了算法，是把 SH 的位宽花到了边际收益最大的地方。

### 2.3 其余 8 个标量：8 bit 免费，6 bit 略亏，4 bit 崩

| 变体 | 码率 | bicycle | flowers | stump | treehill |
|---|---|---|---|---|---|
| `m16_o10_sh4` | 5.62× | −0.46 / 0.13 | −0.60 / 0.09 | −1.22 / 0.26 | −0.12 / 0.02 |
| `m16_o6_sh4` | 6.21× | −0.62 / 0.14 | −0.72 / 0.06 | −1.44 / 0.30 | −0.21 / 0.04 |
| `m16_o4_sh4` | 6.56× | −5.72 / 1.30 | −3.11 / **−0.20** | −6.25 / 0.60 | −2.44 / **−0.74** |

`m16_o4_sh4` 的 ΔPSNR 在 flowers 与 treehill 上是**负的**（量化后反而更接近 GT）：4-bit 不透明度
在低对比场景里造成了模糊，而 PSNR 喜欢模糊——这正是「PSNR 不是覆盖」的又一次实证，
也提醒覆盖率与 PSNR 必须同时报告（M1 的 D2 就是为此设的）。

### 2.4 角落

`m15_o8_sh2` 8.54× −3.62/−3.40/−10.82/−1.24 pp；`m15_o6_sh2` 9.21× −3.72/−3.50/…/…
——两个便宜项**同时**放松就会叠出 3 pp 以上的损失，说明地板是「每项各自的地板」，不是「总量够就行」。

## 3. 官能结论（可直接写进论文）

1. 在 SH degree 3、每基元 48 个 SH 系数的设定下，**44 B 的几何里只有 6 B（位置）必须留着 16 bit**；
   其余 9 个标量 8 bit 无损，6 bit 只花 0.1–0.2 pp。
2. **视图相关项的位宽是主要杠杆**：8→4 bit 几乎免费，4→3 bit 花 0.2–0.4 dB，3→2 bit 崩。
3. 于是 5.9×（16/8/4）与 6.9×（16/8/3）这两个点构成新的近无损前沿，M1 的 4.92× 被推后 20–41%。
4. 位置要 16 bit 的理由**不能**用「绝对精度」解释（0.15 mm 已经很小），只能用「相对 σ」解释——
   这条直接指向 M3 的减阶实验与后续的相对编码。

## 4. 注意事项

- `m16_o8_sh1` 是退化配置：每块 min–max 量化器的 `qmax = 2**(b-1) - 1` 在 b=1 时为 0，导致除零、全 NaN。
  published 量化器的最小可用位宽是 **2 bit**。该变体已从网格删除，分析器也加了 NaN 变体的丢弃保护。
- treehill 的 clean PSNR（9.41 dB）是归档 GT 的曝光失配，**PSNR 不可引用**，覆盖率/SSIM/LPIPS 可用。
- stump 是四个场景里最紧的（基元最密、σ 最小）：16-bit 位置在它身上就已经不是完全免费（−1.23 pp）。
- 本轮 4 个场景同向，没有例外；但只有 4 个资产，泛化性由 M3 的 8 资产（含 4 个 `iteration_7000` 双胞胎）承担。
