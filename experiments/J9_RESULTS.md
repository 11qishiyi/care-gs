# J9 results — the law's适用范围，以及它在哪里失效（2026-11-28 01:30，bicycle + bonsai）

**一句话**：规律**从 α=0.02 到 0.3 都成立**（每档都不重叠），**在 α=0.01 失效**——不是因为量化变差，而是因为
**删除 50% 基元在 99% 覆盖率要求下几乎不再损失任何覆盖率**。另外，预注册的"误差泛函"检验**在构造上是空的**（见 §3），
要换成真正改变排序的聚合方式才能测。

## 2 C1：容差扫描——5/6 成立，1% 处失效

"最不伤的几何编辑"vs"最伤的属性编辑"（pp，正=覆盖率损失）：

| α | 最轻几何 | 最重属性 | 不重叠？ |
|---|---|---|---|
| **0.01** | **−0.04** | 0.01 | **否** |
| 0.02 | 0.08 | 0.02 | 是 |
| 0.05 | 1.52 | 0.05 | 是 |
| 0.10 | 3.61 | 0.09 | 是 |
| 0.20 | 5.70 | 0.23 | 是 |
| 0.30 | 7.20 | 0.94 | 是 |

**失败机制**（从表里直接读出）：α 越小 → 要求覆盖率越高（1−α）→ q 取到残差分布的更远处 → 阈值越高 →
删掉一半基元后绝大多数像素**仍然**在阈值之下。α=0.01 时 bicycle 的 prune50 只损失 **0.56 pp**，bonsai 是
**−0.04 pp**（覆盖率反而微升）。也就是说：

> **规律不是"绝对的"，它以容差足够宽为前提。当要求 99% 像素达标时，删除 50% 基元也几乎不破坏承诺。**

这是一条应当写进论文的边界条件，而不是藏起来。

## 3 C2：预注册的"泛函"检验是空的（自证）

预先写的是"绝对误差 vs 平方误差"。结果：**两种泛函的比值完全相同**（33.02 vs 33.02、39.68 vs 39.68 …），
因为覆盖率 `P(e ≤ q_α)` 是**秩统计量**，任何单调变换（含平方）都不改变秩，q_α 也随之变换。

**这是设计缺陷，我的错**：δ 分位保证对单调重标定不变，所以"换泛函"必须换**排序**，不能换**单位**。
已改为**逐通道最大值**（`--reduction max`）在节点上重测——它真的会改变哪个像素算"坏"。

所以分离不是池化造成的平均效应。

## 5 组合编辑：给剪枝加上量化，救不回来

`prune50+quantB` 相对 `quantB` 单独使用多付出的覆盖率（pp，α=0.1）：

| 场景 | 组合臂 | 组合后损失 | 量化单独 | **净增** |
|---|---|---|---|---|
| bicycle | prune50+quant8 | 7.20 | 0.00 | **+7.19** |
| bicycle | prune50+quant6 | 7.29 | 0.03 | **+7.26** |
| bicycle | prune50+quant4 | 8.17 | 0.44 | **+7.73** |
| bonsai | prune50+quant8 | 22.14 | 0.01 | **+22.13** |
| bonsai | prune50+quant6 | 22.19 | 0.02 | **+22.17** |
| bonsai | prune50+quant4 | 23.85 | 0.94 | **+22.91** |

即：**在同一容器下把两族叠加，删除仍然主导覆盖率损伤**。这直接回应了审稿人 A 的"剪枝臂没编码"——在覆盖率轴上，
即使剪枝用上了容器的量化，它也拿不回那 7–22 pp。**但这不等于率轴的问题已解**：J8 要问的是"同码率下"，
这一轮没有测码率。

## 6 与旧 56 格网格的一致性

α=0.1、bicycle：prune50 = **+3.61 pp**、prune30 = **+24.42 pp**；旧网格记录 prune50 = −4.94（即 4.94 pp 损失）、
prune30 = −22.08。prune30 量级一致；prune50 相差 1.3 pp，来源是**视图集与划分不同**（本轮 13 个部署视图 vs 旧网格
25 个），以及 q 重新校准。**只在轮内比较，不跨轮配对**，与 J7/J8 的约定一致。
