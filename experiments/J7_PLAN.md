# J7 — 覆盖感知剪枝：对 C1 头条的证伪测试（预注册，2026-11-20）

## 0 为什么做这一轮

论文的头条是“**动作族**决定保证能否存活”：ε=1 pp 内量化可达 8.97–15.78×，剪枝**没有任何可行点**。
但剪枝用的是**与覆盖率无关**的打分（Fisher、opacity、volume、area）。审稿人一句就能问：

> 你们用的是 Fisher，不是为覆盖率设计的。换一个为覆盖率设计的打分，结论还成立吗？

现在答不上来。这一轮就是回答它，而且**两种结果都对论文有利**：

| 结果 | 含义 | 处置 |
|---|---|---|
| 覆盖感知打分把同 keep 率下的覆盖率损失降 ≥30% | 头条降级为“打分不好”，但换来一个更真的结论：**这类工作一直在用错的目标函数** | 重写 §5.2 与摘要 |
| 降幅 <10% | 头条升级为“**在最好的打分下依然成立**” | §5.2 加一句“我们试过覆盖感知打分”，C1 加固 |

## 0b 打分器已实现并通过自检（2026-11-20 00:28）`n`n`experiments/j7_score.py --selftest` 八项全过，其中关键一条：**coverage-risk 的 top-50% 与 opacity 的 top-50% 只有 53% 重叠**——`n`即“换打分”确实会选出**不同的半数图元**，实验不是空转。其余检查：线性于 α、平方于尺度、阈值感知（e=q 得 6.36，e=0 得 0）、选择确定。`n`n## 1 打分设计（三种，同一容器、同一 keep 率）

| 打分 | 定义 | 现状 |
|---|---|---|
| **Fisher** | 灵敏度对角（现有） | 已测：−0.50 / −0.53 dB |
| **opacity** | 直接按不透明度 | 已测：−0.93 / −1.28 dB |
| **coverage-risk（新）** | 逐图元“删了会不会把误差推过 $q$”的可微代理 | 本轮实现 |

`coverage-risk` 的闭式近似（不需要逐图元归因）：

$$r_j \;=\; \alpha_j \cdot A_j \cdot \Bigl(1 - \bigl|e_{\mathrm{loc}(j)} - q\bigr|/q\Bigr)_+$$

其中 $\alpha_j$ 不透明度、$A_j$ 屏幕足迹面积（由尺度与相机雅可比给出）、$e_{\mathrm{loc}(j)}$ 是该图元投影中心处干净渲染的绝对残差。
直觉：**在误差已经贴着阈值、且覆盖面积大的像素上贡献多的图元，删除风险最高**；在误差远离阈值处贡献的图元，删了不影响覆盖率。

## 2 协议（开跑前钉死）

| 项 | 取值 |
|---|---|
| 场景 | `bicycle`、`stump`（跨论文那一对） |
| keep 率 | 0.9 / 0.7 / 0.5（与 `tab_prune` 同档，可对照） |
| 度量 | $q$ 下的覆盖率损失（pp）、PSNR、SSIM |
| 判据 | 同 keep 率下 `coverage-risk` 的覆盖率损失 ≤ Fisher 的 **70%**，在 2 场景 × 3 档里至少 4/6 成立 |
| 失败处理 | 若 ≤ Fisher 的 90%（即降幅 <10%），判定“打分不是原因”，写进 §5.2 并加固 C1；介于两者之间则如实报区间 |
