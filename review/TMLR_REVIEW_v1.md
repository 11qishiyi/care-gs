## 1. Summary（我读到的贡献）

作者测量 split-conformal 质量证书在 3DGS 资产被编辑后是否仍然成立。协议：9 个场景（4 个官方发布 checkpoint + 5 个自训），每个留出视角渲染一次，然后做 400 次随机 calibration/deployment 划分，报告覆盖率与配对降幅。结论有三层：

1. 几何编辑（按不透明度剪枝到 30%）使覆盖率从名义 0.90 掉 10.9–18.6 个点；SH 阶数下降掉 0.2–2.0；8-bit SH 量化掉 0.00。
2. **更强的主张**：覆盖率这个证书指标本身低估实际损失——同一批资产，覆盖率只掉 4.6 点，补丁重定位任务掉 16.8 点，四个场景的低估倍数为 1.9–12.1×。
3. 三条实践规则（重签 / 别在量化后重签 / 优先敏感度剪枝）+ 一个负面结果（用标定集自检是循环论证）。

作者还给了 Table 1"主张—证据—反驳条件"对照表，这个做法本身值得肯定：它让评审可以逐条判定证据是否到位。

## 4. BLOCKER（不解决我会投 reject）

### B1. 头号数字（1.9–12.1×）是两种粒度混着算出来的，Table 4 与 Table 2 对同一编辑给出互相矛盾的覆盖率降幅

- **事实**：Table 2 剪 30% 的覆盖率降幅是 −10.9/−18.6/−12.8/−11.7（像素级，`many_splits.json`）。Table 4 的 "Certificate drop" 列写 −4.6/−6.1/−2.6/−6.1——这不是同一量，是 `results_v60/vt_*.json` 里的**世界坐标体素级**降幅。论文正文与 Table 4 标题都没写这个限定。
- **为什么致命**：读者把 Table 2 和 Table 4 并排看，同一场景、同一编辑、同一模型，覆盖率降幅一个 −10.9 一个 −4.6，而全文没有任何一句话解释。审稿人只需要 30 秒就会写下"the two main tables report incompatible numbers for the same quantity"。
- **更麻烦的是**：比值随粒度剧烈变化。同一批任务降幅（−16.8/−21.6/−31.7/−11.9），除以**同粒度**的像素级覆盖率降幅是 **1.02–2.47×**；除以体素级才是 1.93–12.14×。也就是说"低估 2–12 倍"这个卖点**只有在你选体素级当分母时才成立**。
- **最小修法**：Table 4 改成三列（pixel / voxel / task），标题与正文明确写"证书降幅按两种粒度报告"。摘要的头号数字只能用同粒度比较，并说明粒度选择。这条改完，主张会变弱但变成真的。

### B2. 剪 50% 时方向反转：3/4 场景的任务损失**小于**覆盖率损失

- **事实**（`_tmp_verify.py` 输出）：

  | 场景 | 剪 50% 任务损失 | 剪 50% 像素覆盖率损失 | 判定 |
  |---|---:|---:|---|
  | flowers | −1.8 | −3.6 | 任务损失**更小** |
  | bicycle | −2.8 | −5.4 | 任务损失**更小** |
  | treehill | −11.7 | −4.5 | 任务损失更大 |
  | stump | **+0.6（变好）** | −2.1 | 任务损失**更小** |

- **为什么致命**：论文的主张是"证书指标系统性低估损失"。但在一个已经测过、数据已经存在、却没写进论文的编辑强度上，**关系反过来了**，其中一个场景任务还变好了。这不是小的稳健性问题，它说明"低估 N 倍"不是这条曲线的性质，只是剪 30% 那一点的偶然。审稿人一旦自己算出来，会认为作者是选择性报告（哪怕是无意的）。
- **最小修法**：把两个编辑强度都进主表，把主张从"系统性低估 N 倍"改成**"覆盖率与任务效用不同调（not monotone）"**：剪 50% 时覆盖率掉 2.1–5.4 而任务变化 −11.7~+0.6；剪 30% 时两者都掉、任务掉得更多。方向不一致本身才是发现，而且它比"低估 N 倍"更难被反驳。

### B3. §2 对覆盖率的定义与实现不符，读者无法复现"coverage"到底是什么

- **原文**（L132–137）："Coverage is a view-level quantity: the effective sample size is the number of views (16–25), not the number of pixels."
- **实现**（`many_splits.py`）：`q = 分位数(cal 全部像素展平)`；`coverage = (dep 全部像素 ≤ q).mean()`。它是**像素级比例**，每个划分里 dep 有约 10^6 个像素；视角只在**重采样**层面是单位。
- **为什么致命**：证书的定义（L124–130）是像素级分位数，§2 却说覆盖率是视角级量，两句话自相矛盾；审稿人无法判断 Q：这个 0.900 是"下一个视角以 0.9 概率达标"还是"90% 的像素达标"。摘要（L24–25）又写成 "the rendering error on a held-out view stays below a threshold q"——这是第三种说法。
- **附带问题（也是可以变成加分项的机会）**：如果按像素独立算，0.9 的覆盖率在 10^6 像素上的抽样标准差是 3×10⁻⁴，而实测划分间标准差是 0.018–0.040。用 n_eff = 0.9·0.1/sd² 反推，**有效独立分数只有 56–277 个**（四个场景）。这恰好证明"视角间异质性主导方差"——也就是说作者的直觉是对的，只是写错了。把这套论证写进 §2，既修了 B3，又白得一个"我们量化了有效样本量"的亮点。

### B4. 下游证据只有一个任务、阈值由作者自选，而论文自己列的"反驳条件"没有做

- **原文**：Table 1 明写这条主张"would be refuted if ... **the gap disappears once the task threshold is varied**"（L101–103）。全文没有做这个变化。tol=2px、peak≥0.6、patch=32、search=±24 四个参数一个都没扫。
- **为什么致命**：TMLR 标准 #1 问的就是"证据是否 convincing"。一个自己承认的关键反驳条件没做，等于把最容易被攻的地方留给审稿人。而且模板匹配类任务对 peak 阈值极其敏感（peak≥0.6 对 treehill 这种低纹理场景可能已经在饱和区），完全可能某个合理参数下"低估"消失。
- **最小修法**：跑 4×4×3 左右的参数网格（patch ∈ {24,32,48}, tol ∈ {1,2,4}, peak ∈ {0.3,0.45,0.6,0.75}, search ∈ {16,24,32}），报告"在 X/Y 个配置下 30% 剪枝的任务降幅 > 覆盖率降幅"，并给一个配置间的范围而不是单点。这需要重渲染（约 30–60 分钟 GPU），是本次 revision 最值得花的一笔算力。

### B5. 第一贡献是同义反复：编辑破坏保形有效性是定义的直接推论

- **原文**：标题、摘要第一句、Contribution 1（L65–68）都以"编辑使证书失效"为主线。
- **为什么致命**：split-conformal 的有效性依赖 calibration 与 deployment 分数的可交换性；模型变了，分数分布就变了，有效性**本来就不该成立**。懂 conformal 的审稿人 30 秒后会写 "this is a corollary of exchangeability, not a finding"。论文真正非平凡的东西是**幅度**、**粒度依赖**、以及**有效但无用（valid but useless）**。
- **最小修法**：把"失效"降级为背景/设置，把主线换成"**证书有效 ≠ 资产可用**"：重签之后覆盖率回到 0.88–0.97（Table 5a），同一批资产的补丁重定位仍比干净资产低 12–32 点（Table 4）。这条主张不需要任何新数据，但它把论文从"复述定义"变成"测量一个反直觉的解耦"。

## 5. MAJOR（会显著降低接受概率）

### M1. 4 个场景的效应 + 5 个弱模型当反例，外推链条太细
发布 checkpoint 只有 4 个（flowers/bicycle/treehill/stump），它们是唯一支撑 10.9–18.6 的证据；另外 5 个自训场景是 11–16 dB 的弱模型，论文自己说"效应不在那里出现"。于是"9 个场景"的实际信息量是 **4 个**。审稿人会问：为什么不把 Mip-NeRF 360 剩下 5 个场景的官方 checkpoint 也测了？如果数据可得性是真限制，请在 §2 明写来源与限制（"the public pretrained archive ships models for four of the nine scenes"），不要用"9 个场景"包装。

### M2. 区域粒度（voxel/block）决定头号数字的量级，却只在附录
像素级 −10.9–18.6 vs 体素级 −2.6–6.1，差 3–4×。而**现实里签发的证书多半是区域/载波级的**（AURA 是 per-carrier 平均不可靠度）。那么主表应当同时给 pixel 与 region 两列，摘要必须带粒度限定。现在把 3–4× 的差异藏在附录 C（L466–470），等于把最重要的敏感性分析埋在读者找不到的地方——审稿人找到后会认为这是回避。

### M3. "重签只需 2–4 个视角"是机械结果；"26–71% 宽度代价"不是同一配置下测的
- Table 5a：n=2 时覆盖率 0.882–0.971，n=4 时 0.901–0.969，n=all 时 0.876–0.927。任何 n 都"接近名义"，因为重标定后保形有效性本来就恢复——这条规则没有实验含量。
- 摘要把"2–4 视角"与"26–71% 更宽"并置，但后者是在**全部**标定视角下算的（`widths.json`），2–4 视角下的宽度没测（那会宽得多）。
- 真正有信息量的量是：**要恢复原来的区间宽度需要几个视角**，或**在固定宽度预算下覆盖率能到多少**。这个曲线可以离线从已有的 per-split 分位数算（若有 per-view 残差），是最便宜的高价值补测。

### M4. 400 次划分不是独立重复，报告的是"划分散布"而不是置信区间
摘要（L27–28）称 "paired confidence intervals"，§3.1 称 "brackets are 2.5/97.5 percentiles"。400 次划分是在同一批 16–25 个视角上做的重采样：它们刻画的是"标定集换一批视角会怎样"，不是场景级不确定性，也不构成对某个总体参数的 95% CI。建议：改称 "split-to-split intervals"，并补一句"the brackets quantify sensitivity to calibration-set composition; asset-level uncertainty is not estimated"。这不会削弱论文，反而显示作者知道自己在报告什么。

### M5. 比值（1.9–12.1×）不是可外推的统计量，跨 6 倍离散本身就否定了它
分母是 2.6–6.1pp 的小差值，分子是 11.9–31.7pp 的任务差异，比值对粒度（B1）、编辑强度（B2）、阈值（B4）都敏感。把"1.9–12.1×"当卖点，等于把一个不稳健的商放在摘要里。建议：主结论用绝对百分点 + "排序/方向"陈述，比值只在表里给并明确标注不可外推。

### M6. 关键相关工作引而未用：conformal under distribution shift
`tibshirani2019` 在参考文献里，正文 0 次使用。而这正是本文的理论框架：编辑后的部署视角相对标定视角发生了 covariate shift，Tibshirani et al. 的加权保形给出了"知道似然比时如何恢复有效性"的答案。论文应当（a）用它把自己的测量定位成"量化 exchangeability 被破坏的后果"，(b) 说明为什么加权保形在**无标签**场景下帮不上忙（拿不到部署侧分数），(c) 若能顺手测一次"用可见协变量做加权"（代码里 `weighted` 模式已经存在）会显著加分。
